# 从零创作 Crescent Lake 的实现 Prompt

请在一个独立、受 Git 管理的工程中，从零创作一幅名为 **Crescent Lake** 的可交互数字艺术，并交付可运行源码和实际导出成片。请直接实施、测试和修正。

创作主题是：**一只白天鹅游过安静的湖面，风掠过草岸，光线从清晨变成金色时刻，再回到清晨。** 作品应适合以竖屏循环短片分享，有插画般的审美和完整的视听体验。

下面规定作品的核心体验。具体色彩、造型、字体、构图细节、着色算法与音乐语言，请根据整体艺术方向自行设计；用户有偏好时优先采用。先简洁说明你的美术方向，随后继续完成实现。

## 画面与艺术方向

- 默认 9:16 竖屏。使用固定、略俯视的镜头，优先考虑正交投影。蜿蜒草岸从画面左侧延伸，湖面保留大面积留白，白天鹅是视觉重心。岸面有足够的展示空间，天鹅完整的游动路线始终在画面内。
- 整体清新、安静、克制，以 **Cel Illustration** 为主要视觉方向。通过造型、色块、光影层次和材质细节建立插画感，保持清晰；纸感和柔和边缘可以点到为止。
- 自行设计三套协调但有区别的配色。可以探索清晨薄雾、暖光、深色水面等气质，具体颜色、饱和度和命名由你决定。白天鹅在每套配色里都应清楚而自然。
- 可额外探索少量有实质差异的渲染风格，如水彩、版画、印刷或像素表达。选择适合画面的算法，先保证主要风格精致完整。
- 页面文字全部英文。自行挑选有艺术气质、适合屏幕阅读的本地字体，让标题、短句、留白与画面共同构成海报。文案可以自行创作，数量保持克制。

## 场景与动态

- 从零建立天鹅造型：自然弯曲的长颈、完整身体、独立羽翼和可读的轮廓。可采用程序化几何或脚本建模，保持统一的插画语言。描边轻柔，以外轮廓为主，避免内部羽毛和阴影变成杂乱黑线。
- 草地覆盖所有可见岸面，包括左上方腹地。草叶的长短、弯曲、朝向和疏密有变化，色调柔和，避免根部黑点、强对比和重复排列造成脏乱感。
- 风要同时影响草、树和湖面。草随阵风成片摆动，叠加局部差异；树干与树冠有轻微但可见的运动。加入缓慢飘过的云和远处飞鸟，支持分别关闭。
- 湖面保留镜湖般的平静与可读的倒影。风吹过时，全湖出现轻柔、半透明、长短不同、随机断续的弯曲波纹。风力增大时变化明显，但仍然克制，避免整齐的大斜条、密集细噪声和局部 Wi-Fi 状波纹。
- 天鹅身后留下细密、舒展、持续扩散的扇形弧线尾迹，留存足够久，再自然渐隐。天鹅转弯时，旧尾迹保持在原来的水面位置；游速变化后，尾迹仍保持优雅的密度与空间比例。
- 天鹅有细微呼吸和身体屈伸，间歇突然快速抖动几下翅膀，随后恢复安静。动作要明显、有轻重变化，羽翼始终连接肩部。
- 默认状态已经有可见的风和天鹅动作；用户可以从静止调到更活跃，较强设置也保持自然姿态。随机变化应有组织，避免所有物体机械地同步摇摆。

## 光线与循环

- 默认完成一个 **24 秒循环**，天鹅在其中游完一整圈。若艺术节奏需要调整，总时长不超过 26 秒。
- 光线完成 **Morning → Golden Hour → Morning**。金色时刻应有温暖高光、较低的光照方向与更长的阴影，同时保留冷色暗部和配色特点。
- 天鹅位置、姿态、草树、云鸟、水纹、历史尾迹和光线都应首尾连续。可使用周期运动、可循环噪声或其他合适方案，让随机感与循环兼容。
- 使用统一的场景时钟。暂停时所有运动同步冻结，导出时按精确帧时间推进，避免性能波动改变成片速度。

## 原创配乐

- 用代码合成原创配乐，可采用 Web Audio 或合适的声音工具。音乐柔和、灵动、有空间感，和画面的宁静气质一致。
- 让和声、连奏旋律、低音及克制的节奏形成层次；用较低音区或较厚的音色回应高音旋律。音色、调式、和弦、拍号与速度由你设计，避免生硬的逐音敲击和高频堆叠。
- 主要层次在前几秒就能听见，短片中有呼吸和变化。适度使用滤波、延迟与混响，并通过缓慢的左右声道运动建立空间回环感，低音保持稳定。
- 音乐与画面同周期循环，保留自然的混响尾音。结尾不能突然截断，也不要依靠淡到静音隐藏接缝。实际检查双声道和循环接点。

## 页面与导出

- 页面适配屏幕，无页面滚动条。所有控件集中到可收起的右侧面板；9:16 / 16:9 在同一页面内切换。复用现有开发服务。
- 提供暂停、配色、风格、风力、天鹅动作、云鸟开关、音乐开关、保存图片和视频导出。成片只包含艺术画面及作品文字，隐藏所有控件和工程性标签。
- 导出原生 **2160×3840、30fps** 的竖屏 4K MP4，并提供真正无损的 RGB 视频与 PCM 音频母版，例如 FFV1 / MKV。实际提高场景、倒影、后处理和文字的渲染分辨率。
- 无损导出采用逐帧渲染和编码，以精确时间取样；24 秒对应 720 帧。控制内存占用，支持取消和失败清理。高质量分享版与无损母版分别标明。
- 若需要本地导出服务，将其限制为本机同源访问，并对尺寸、帧数、并发和磁盘占用设置合理限制。

## 工程与交付

- 优先考虑 Three.js、TypeScript、Vite 与自定义 GLSL，也可选择更适合此艺术方向的方案。运行时模型、字体等资产随工程提供，源码按职责合理组织。
- 在独立 Git 工程中分阶段提交。提供简洁的中英文 README、启动及导出说明和小尺寸预览图。视频、音频、帧序列、校验数据、依赖和构建产物放入忽略目录。
- 优先使用内置浏览器，按现代社交媒体的竖屏尺寸检查构图、文字安全区与完整游动路线。实测不同配色、清晨与金色时刻、风力变化、快抖翅及尾迹表现。
- 实际导出完整一圈，检查循环接点、音画同步和声音层次。验证文件尺寸、时长、帧数与编码，并用解码后逐像素比较等方式确认无损母版与源渲染一致。
- 最终交付可运行工程、已验证的成片与无损母版本地路径、Git 提交信息，以及简短的验证结果。
