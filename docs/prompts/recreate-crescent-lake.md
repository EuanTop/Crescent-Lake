# 复现 Crescent Lake 的实现 Prompt

请在一个独立、受 Git 管理的工程中，实现一幅名为 **Crescent Lake** 的可交互数字艺术，并交付完整源码和实际导出成片。请直接实施、测试和修正，不要只提供方案。

参考作品：https://www.behance.net/gallery/257725777/Crescent-Lake
开源实现：https://github.com/EuanTop/Crescent-Lake

可阅读并按许可证复用开源实现；如果从零实现，按以下要求完成。不要用播放预渲染视频、整张图片或嵌入参考页面代替实时场景。

## 画面与视觉语言

- 默认 9:16 竖屏艺术海报：固定、略俯视的正交镜头，左侧是蜿蜒的草岸，右侧大面积湖面留白，一只白天鹅是视觉重心。竖屏中要看见足够的草岸，整条游动路径都不能裁掉天鹅。
- 清新、安静、克制的插画质感。默认 **Cel Illustration**，用有设计的色块、少量光照层次和柔和纸面边缘建立风格。清晰来自几何、配色和着色设计，不能靠全屏模糊滤镜掩盖问题。
- 天鹅有自然弯曲的长颈、完整身体和独立羽翼。可以用 Blender 脚本生成并导出自包含 GLB，也可以程序化建模。描边只强调外轮廓，不能把羽毛交叠和内部阴影描成杂乱黑线。
- 草地覆盖所有可见岸面，包括左上方腹地；草叶长短、朝向、弯曲和疏密有变化。降低根部黑点和亮暗对比，不要让草岸显得脏或像重复贴片。
- 提供 Soft Sage（柔和青绿）、Blue Reverie（钴蓝湖水与象牙白）和 Wild River（橄榄绿湖水与鲜绿草岸）三种协调配色。
- 额外可切换 Watercolor、Risograph、Copperplate、Pixel Story、Cyanotype 和 Original。不同风格应使用相应的色阶、颜料颗粒、网点、排线或抖色算法；避免把一切都做成模糊效果。
- 页面文字全部英文。标题用有个性的本地字体，如 Goudy Bookletter 1911，保留许可。文字与画面共同构成海报，可用 “Crescent Lake” 和 “Where the water slows.”；不要出现工程预览标签。

## 水、风与天鹅

- 水面保留镜湖感和可读的倒影。风吹过整个湖面时出现克制、半透明、长短不一、有柔和断续的弯曲波前。风越强，动态越明显。不要密集细噪点、整齐大斜条纹或局部 Wi-Fi 状小波包。
- 天鹅尾迹是细密、连续、舒展的扇形弧线，向后扩散并渐隐。记录发射时的世界坐标和朝向，不能在天鹅转弯时让旧尾迹一起旋转。
- 提高游速时，尾迹生成密度、扩散和消散必须同步调整，保持原有空间比例。参考：24 秒一圈，约 215 次发射，每次相隔约 0.112 秒，约 55 条可见弧线；用统一加速的尾迹时钟，避免稀疏小圆圈或绕满整圈的白色尾迹。
- 草叶随大尺度阵风成片摆动，再叠加每株的细小变化；树干从根部轻微倾斜，树冠有独立摆动。云缓缓穿过，远处小鸟飞过并扇翅，可独立关闭。
- 天鹅安静游动时有细微呼吸和屈伸；时不时突然连抖 3–4 下翅膀，约 0.7–0.9 秒完成，抬起和收回之间约 0.22–0.25 秒，随后停歇数秒。不要做成一直慢慢晃动或持续飞行。羽翼始终连接肩部。
- Wind strength 和 Swan movement 默认 100%，可调 0–200%；零值确实停止对应动作。默认抬翅清晰可见，较强设置也必须有安全的姿态上限。

## 一个完整的 24 秒循环

- 天鹅在 **24 秒内完成整圈**，不是缓慢游半圈。光线为 **Morning → Golden Hour → Morning**，12 秒最暖，24 秒回到清晨。
- Golden Hour 要有蜂蜜色高光、较低的太阳和更长的阴影，保留冷色暗部与调色板差异，不能只是全屏加橙色。
- 云、鸟、树、草、水纹、天鹅姿态和历史尾迹都要首尾衔接。随机变化需固定种子并保持时间连续；用整数周期、周期噪声或圆形噪声采样，避免最后一帧跳变。
- 按实际成片时钟或精确帧时间推进，不依赖机器刚好能实时跑满帧率。暂停时所有运动同步冻结，参数变化不造成位置突跳。

## 原创配乐

- 用 Web Audio / 代码合成原创声音，不依赖外部歌曲。气质柔和、灵动、有空间感，有和弦、连奏旋律、较低音区的回应、温暖低音和克制节奏。
- 避免幼稚的逐音钢琴敲击、尖锐铃声和一直堆高频。长旋律中的音高变化不要重新触发音量包络。主要层次在前几秒进入，不能等十多秒后才完整。
- 可采用 70 BPM、6/8 拍，24 秒为 14 小节；以 Fmaj9 → Am9 → G6/9 → Cmaj9 为和声骨架。低音围绕根音与五度，保留休止。
- 旋律有缓慢的左右声道往返；8 秒一个空间周期、24 秒三次回环，低音保持居中。使用滤波、延迟、适量混响建立层次。
- 音乐首尾衔接，不要突然截断或在结尾淡到静音。可先离线合成连续数圈，截取带有上一圈混响尾音的稳定一圈，并消除采样接缝。视频使用双声道，允许导出原始 WAV。

## 页面、控件和导出

- 页面适配屏幕，不出现页面滚动条。所有调节在可隐藏的右侧面板中；9:16 / 16:9 是同一页面内的选项，不跳新页面、不另开开发端口。
- 成片只包含画面和作品文字，不包含面板、按钮、浏览器界面或 “PORTRAIT REVIEW / LIVE SCENE” 等工程性文本。
- 提供暂停、保存 PNG、音乐开关、配色、风格、风力、天鹅动作、云鸟开关和视频导出。
- 提供原生 **2160×3840、30fps、24 秒** 的 4K MP4，以及真正无损的 **FFV1 RGB + PCM / MKV** 母版。同步提高场景、后处理、倒影和文字的实际渲染分辨率，不能把旧 1080p 视频放大再编码。
- 无损路径逐帧渲染全部 720 帧，按 `frameIndex / 30` 取样，逐帧流式送入本地 FFmpeg，不能依赖实时录屏，不能把大量帧长期堆在内存。分享版使用高质量 H.264 / AAC；高码率 MP4 不得标成无损。
- 本地导出服务复用开发服务器，只接受本机同源请求。限制尺寸、帧数、请求体、任务并发和磁盘使用，支持取消并清理未完成文件；完成的文件应保留。

## 工程与验收

- 优先 Three.js + TypeScript + Vite + 自定义 GLSL；模型、字体等运行时资产本地化并保留许可。源码按场景、水、植被、天鹅、天空、音乐和导出拆分。
- 在独立 Git 工程中分阶段提交。README 中英文双版本，简洁、有小尺寸预览图。视频、音频、逐帧序列、校验数据、`node_modules/` 和 `dist/` 不入 Git，统一放入忽略目录。
- 优先用内置浏览器测试，不依赖个人浏览器的登录或 Cookie。**按现代社交媒体竖屏检查**，不能只在横屏看效果。
- 实测清晨、金色时刻、三种配色、明显的快抖翅、岸面覆盖和扇形尾迹。验证完整一圈、首尾姿态与光线、音频双声道和采样接缝。
- 验证实际导出文件的尺寸、时长、帧数和编码；无损母版解码后，与源渲染帧逐像素比较。运行有意义的自动化检查，处理资源释放、取消和失败恢复。
- 最终交付可运行工程、清晰的本地成片地址、无损母版及 Git 提交信息。不要只说“已实现”，要真正导出并检查文件。
